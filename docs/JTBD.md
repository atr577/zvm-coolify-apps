# Jobs To Be Done (JTBD)

Документ описывает ключевые задачи пользователей, которые решает REGGY.

**Основной пользователь:** Контент-мейкер / SMM-менеджер, который хочет автоматизировать создание коротких видео для соцсетей.

---

## 1. Setup (настройка проекта)

> **Когда** я запускаю новый контент-проект,
> **я хочу** настроить пайплайн один раз (промпты, модели, расписание),
> **чтобы** потом система работала автоматически, а я только модерировал.

**Что включает:**
- Выбор моделей (LLM, Image, Video)
- Настройка промптов (preprocessing, image, video, metadata)
- Загрузка вариантов (CSV с START_SPEC)
- Создание video templates
- Настройка расписания публикации
- Привязка соцсетей

**Частота:** Один раз при создании проекта, редкие изменения.

---

## 2. Batch Generation (генерация контента)

> **Когда** у меня есть таблица с идеями (START_SPEC / variants),
> **я хочу** запустить генерацию на все или часть вариантов,
> **чтобы** получить готовые видео для модерации.

**Что включает:**
- Выбор вариантов для генерации
- Запуск batch-генерации
- Мониторинг прогресса
- Просмотр результатов (image, video)

**Частота:** По мере необходимости, когда очередь пустеет.

---

## 3. Moderation (модерация контента)

> **Когда** система сгенерировала видео,
> **я хочу** быстро просмотреть и решить (одобрить / перегенерировать / отклонить),
> **чтобы** в публикацию попадал только качественный контент.

**Что включает:**
- Просмотр видео
- Просмотр метаданных (title, description)
- Approve → видео встаёт в очередь публикации
- Regenerate → новая генерация с фидбеком
- Reject → видео в архив, следующий вариант

**Частота:** Регулярно, основная ежедневная операция.

**Важно:** Пользователь должен понимать, в какой слот расписания попадёт видео при approve.

---

## 4. Publishing (публикация)

> **Когда** видео одобрено,
> **я хочу** чтобы оно автоматически встало в слот расписания и опубликовалось,
> **чтобы** мне не нужно было следить за таймингом публикаций.

**Что включает:**
- Автоматическое распределение по слотам (FIFO)
- Публикация по расписанию
- Ретраи при ошибках
- Уведомления о проблемах

**Частота:** Автоматически, пользователь только проверяет.

---

## 5. Monitoring (мониторинг)

> **Когда** конвейер работает,
> **я хочу** видеть состояние системы одним взглядом,
> **чтобы** вмешиваться только когда нужно.

**Что включает:**
- Сколько видео в очереди модерации
- Сколько одобрено, ждёт публикации
- Когда следующая публикация
- Есть ли ошибки/проблемы
- Хватает ли контента на N дней вперёд

**Частота:** При входе в систему, быстрая проверка.

## User Flow (идеальный)

```
┌─────────────────────────────────────────────────────────────────┐
│                        SETUP (один раз)                         │
│  Settings → Variants (CSV) → Templates → Schedule → Social      │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                    DAILY OPERATIONS (цикл)                      │
│                                                                 │
│   Generate → Moderation Queue → Approve → Publishing Queue      │
│       ↑                           ↓                             │
│       └──── (если очередь пустеет) ←──── Auto-publish           │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                      MONITORING (dashboard)                     │
│  [ Pending: 5 ] [ Approved: 12 ] [ Next: Mon 18:00 ] [ OK ✓ ]  │
└─────────────────────────────────────────────────────────────────┘
```

## Приоритет Jobs

| # | Job | Приоритет | Статус в UI |
|---|-----|-----------|-------------|
| 1 | Setup | High | Частично (Settings отдельно, нет guided flow) |
| 2 | Batch Generation | High | Частично (только по 1 за раз) |
| 3 | Moderation | Critical | Есть, но не связана с расписанием |
| 4 | Publishing | High | Есть (T21) |
| 5 | Monitoring | Medium | Нет dashboard |

---

## Gaps (что не покрыто)

1. **Onboarding flow** — новый пользователь не понимает с чего начать
2. **Batch generation** — нельзя запустить генерацию на 10 вариантов сразу
3. **Moderation ↔ Schedule link** — при approve не видно в какой слот попадёт видео
4. **Dashboard** — нет единого view состояния конвейера
5. **Auto-generation** — система не поддерживает очередь автоматически (T23)
