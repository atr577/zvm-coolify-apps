# UX Audit: Template Video Workflow

**Дата:** 2026-02-03

Аудит текущего UX template-проектов на основе JTBD (`docs/JTBD.md`).

---

## Текущий порядок табов

| # | Tab | JTBD |
|---|-----|------|
| 1 | **Generate** | Job 2: Batch Generation |
| 2 | **Moderation** | Job 3: Moderation |
| 3 | **Publishing** | Job 4: Publishing |
| 4 | **Variants** | Job 1: Setup |
| 5 | **Templates** | Job 1: Setup |

**Settings** — отдельная страница `/project/:id/edit`.

---

## Проблема 1: Tab order не соответствует user flow

JTBD определяет порядок: **Setup → Generate → Moderate → Publish → Monitor**.

Текущий UI: **Generate → Moderation → Publishing → Variants → Templates**.

Пользователь открывает новый проект и видит первый таб Generate. Но генерировать нечего — нет ни вариантов, ни шаблонов. Нужно сначала перейти на 4-й и 5-й табы.

**Следствия:**
- Новый пользователь не понимает с чего начать
- Variants и Templates — prerequisites для генерации, но стоят после неё
- Нарушена ментальная модель "слева направо = порядок действий"

---

## Проблема 2: Setup размазан по 3 местам

Настройка проекта (Job 1) разбита:

| Что | Где |
|-----|-----|
| Модели, промпты, соцсети | Settings page (`/project/:id/edit`) |
| CSV-данные | Tab "Variants" |
| Video шаблоны | Tab "Templates" |
| Расписание публикации | Tab "Publishing" (config form) |

Для пользователя "настроить проект" — единая задача. Но в UI это 4 разных места. Нет guided flow — нужно самому догадаться, что и где настраивать.

---

## Проблема 3: Generate tab не показывает prerequisites

`GenerationPanel` проверяет наличие вариантов и шаблонов, но:
- Показывает только текстовое сообщение об ошибке
- Нет прямой ссылки/кнопки для перехода на нужный таб
- Не показывает прогресс настройки ("2 из 4 шагов выполнено")

---

## Проблема 4: Нет batch-генерации

JTBD 2 говорит: "запустить генерацию на все или часть вариантов". Текущий UI позволяет генерировать **только по 1 за раз** — выбрать вариант, выбрать шаблон, нажать Generate. Для 50 вариантов нужно нажать кнопку 50 раз.

---

## Проблема 5: Moderation не связана с Publishing Schedule

JTBD 3 говорит: "пользователь должен понимать, в какой слот расписания попадёт видео при approve".

Текущий UI:
- Approve просто добавляет видео в очередь (FIFO)
- На экране модерации нет информации о следующем свободном слоте
- Пользователь должен сам переключиться на Publishing tab, чтобы увидеть результат

---

## Проблема 6: Нет единого dashboard / monitoring

JTBD 5 (Monitoring) не реализован. Нет view, который показывает:
- Сколько видео на модерации
- Сколько одобрено / ждёт публикации
- Когда следующая публикация
- Хватает ли контента на N дней вперёд
- Есть ли ошибки

Пользователь вынужден переключаться между табами, чтобы собрать эту картину.

---

## Проблема 7: Publishing tab совмещает config и calendar

Tab "Publishing" содержит:
1. Config form (дни, время, depth) — setup-задача (разовая)
2. Schedule view (календарь слотов) — monitoring-задача (регулярная)
3. Queue view (очередь) — monitoring-задача

Config и monitoring — разные jobs с разной частотой использования. Config настраивают один раз, calendar смотрят каждый день.

---

## Проблема 8: Rating на Generate tab, но Moderation — отдельно

На Generate tab есть inline rating (звёзды + комментарий). На Moderation tab — approve/reject/regenerate. Это два разных UI для оценки одного и того же контента. Непонятно: зачем рейтить на Generate, если решение принимается на Moderation?

---

## Сводка по JTBD

| Job | Статус в UI | Проблемы |
|-----|------------|----------|
| **1. Setup** | Размазан по 3 местам | Нет guided flow, нет прогресс-бара, новый пользователь теряется |
| **2. Batch Generation** | Только по 1 за раз | Нет массовой генерации, нет выбора нескольких вариантов |
| **3. Moderation** | Работает | Не показывает в какой слот попадёт видео при approve |
| **4. Publishing** | Работает | Config и monitoring смешаны в одном табе |
| **5. Monitoring** | Не реализован | Нет dashboard, нет сводки состояния конвейера |
